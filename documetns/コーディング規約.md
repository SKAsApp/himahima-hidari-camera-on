# hidari-camera-on C#コーディング規約

## (1) 適用範囲

本規約は、作成および修正する全てのC#ソースコードに適用します。

本規約に記載のない事項は、プロジェクト内の既存コードとの一貫性、可読性、保守性を優先して判断します。

## (2) 基本方針

- ソースファイルの先頭には、次のコメントを記載します。

```csharp
// Copilot作成
```

- コメント、XMLドキュメントコメント、ログメッセージ、例外メッセージは日本語で記載します。
- 名前空間、クラス名、メソッド名、プロパティー名、フィールド名、ローカル変数名などの識別子は英語で記載します。
- 識別子は意味が分かる名称とし、不必要な省略を避けます。
- C#で一般的な命名規則に従います。
  - クラス、インターフェイス、列挙型、メソッド、プロパティー、定数はPascalCaseとします。
  - privateフィールド、引数、ローカル変数はcamelCaseとします。
  - 非同期メソッド名には`Async`を付けます。
- 型推論キーワードの`var`は可能な限り使用せず、具体的な型を明記します。
- インスタンスメンバーを参照するときは`this.`を付けます。
- 標準で利用できる例外型を優先し、カスタム例外型の作成は必要最小限にします。
- 原則として、1つの`.cs`ファイルには1つのクラス、インターフェイス、列挙型、レコードのいずれか1つだけを記載します。

## (3) 字下げと改行

- 字下げにはハードタブを使用します。
- 波括弧はAllmanスタイルで記載します。
- 制御構文の処理が1行だけの場合も、波括弧を省略しません。

```csharp
if (condition)
{
	return;
}
```

- 制御構文キーワードと開始丸括弧の間には、半角スペースを1つ入れます。

```csharp
if (condition)
{
}
```

- メソッドの宣言および呼び出しでは、引数の丸括弧内を見た目だけの理由で改行しません。
- 値の代入は1行で記載します。
- `return`の直前に、意味のない空行を入れません。
- ログ出力の前後に、意味のない空行を入れません。
- 処理上の意味的な区切りがある場合だけ空行を使用します。
- コンストラクターやメソッドの本体を1行に圧縮しません。

## (4) 丸括弧内の空白

- 丸括弧内が空の場合は、半角スペースを1つ入れます。

```csharp
this.BadRequest( );
```

```csharp
public ActionResult Get( )
{
}
```

- 丸括弧内に引数や条件がある場合は、括弧の内側に空白を入れません。

```csharp
this.normalizationService.NormalizeComment(request.Text);
```

```csharp
if (!result.Success)
{
}
```

## (5) 波括弧と初期化子

- 制御構文では、処理が1行だけでも必ずブロックを記載します。

```csharp
if (!result.Success)
{
	return this.BadRequest( );
}
```

- オブジェクト初期化子は、開始波括弧、各メンバー、終了波括弧をそれぞれ別の行へ記載します。

```csharp
return new CameraEventResponse
{
	RequestId = requestId,
	Accepted = true,
	Triggered = triggered,
	Duplicate = duplicate,
	ObsOperation = operation,
	Message = message
};
```

## (6) XMLドキュメントコメントの基本分類

XMLドキュメントコメントの形式は、対象を次の2種類に分類して決定します。

### (6-1) 処理系

メソッド、コンストラクター、クラスなど、通常は`summary`以外に`param`、`returns`、`typeparam`などのタグが付く対象を処理系とします。

処理系の`summary`は複数行形式で記載し、説明はです・ます調とします。

```csharp
/// <summary>
/// コメントを受け付けて発動判定します。
/// </summary>
```

### (6-2) 値系

インスタンス変数、プロパティー、列挙値など、通常は`summary`だけが付く対象を値系とします。

値系の`summary`は1行形式で記載してよく、説明は体言止めを優先します。

```csharp
/// <summary>コメント文字列を正規化するサービス</summary>
private readonly TextNormalizationService normalizationService;
```

```csharp
/// <summary>要求識別子</summary>
public string RequestId { get; set; } = string.Empty;
```

```csharp
/// <summary>未接続状態</summary>
Disconnected,
```

## (7) クラスのXMLドキュメントコメント

- すべてのクラスには、複数行形式の`summary`を記載します。
- クラスの動作または責務を、です・ます調で説明します。
- ジェネリック型引数がある場合は、すべての型引数に`typeparam`を記載します。

```csharp
/// <summary>
/// コメント受付APIを提供します。
/// </summary>
public sealed class CommentsController : ControllerBase
{
}
```

## (8) フィールドのXMLドキュメントコメント

- インスタンスフィールドには、1行形式の`summary`を記載します。
- 説明は体言止めを優先します。
- ローカル変数にはXMLドキュメントコメントを記載しません。

```csharp
/// <summary>コメントの発動条件を判定するサービス</summary>
private readonly CommentTriggerMatcher matcher;
```

## (9) プロパティーのXMLドキュメントコメント

- すべてのプロパティーには、1行形式の`summary`を記載します。
- 説明は体言止めを優先します。
- 「取得または設定します」のような定型句より、値の意味を具体的に記載します。

```csharp
/// <summary>OBS Studio操作の結果</summary>
public string ObsOperation { get; set; } = "notRequired";
```

## (10) 列挙型と列挙値のXMLドキュメントコメント

- 列挙型には、複数行形式の`summary`を記載します。
- 列挙型の説明は、です・ます調とします。
- 各列挙値には、1行形式の`summary`を記載します。
- 列挙値の説明は、体言止めを優先します。

```csharp
/// <summary>
/// OBS Studioとの接続状態を表します。
/// </summary>
public enum ObsConnectionState
{
	/// <summary>未接続状態</summary>
	Disconnected,

	/// <summary>接続処理中</summary>
	Connecting
}
```

## (11) コンストラクターのXMLドキュメントコメント

- コンストラクターには、複数行形式の`summary`を記載します。
- `summary`は、です・ます調で処理を説明します。
- すべての引数に対応する`param`を記載します。
- `param`の説明は、体言止めを優先します。

```csharp
/// <summary>
/// コントローラーを初期化します。
/// </summary>
/// <param name="normalizationService">コメント文字列を正規化するサービス</param>
/// <param name="matcher">コメントの発動条件を判定するサービス</param>
/// <param name="triggerService">カメラの表示処理を実行するサービス</param>
public CommentsController(TextNormalizationService normalizationService, CommentTriggerMatcher matcher, CameraTriggerService triggerService)
{
	this.normalizationService = normalizationService;
	this.matcher = matcher;
	this.triggerService = triggerService;
}
```

## (12) メソッドのXMLドキュメントコメント

- すべてのメソッドには、複数行形式の`summary`を記載します。
- `summary`は、です・ます調で処理を説明します。
- すべての引数に対応する`param`を記載します。
- `param`の説明は、体言止めを優先します。
- 戻り値がある場合は`returns`を記載します。
- `returns`は、戻り値の内容を具体的に記載し、体言止めを優先します。
- `void`メソッドには、原則として`returns`を記載しません。
- 例外を呼び出し元へ通知することが仕様上重要な場合は、必要に応じて`exception`を記載します。

```csharp
/// <summary>
/// コメントを受け付けて発動判定します。
/// </summary>
/// <param name="request">コメント受付APIの要求情報</param>
/// <param name="cancellationToken">非同期処理の取り消しを通知するトークン</param>
/// <returns>コメントの受付結果とカメラ操作結果</returns>
public async Task<ActionResult<CameraEventResponse>> PostAsync([FromBody] CameraEventRequest request, CancellationToken cancellationToken)
{
}
```

## (13) 通常コメント

- 通常コメントは日本語で記載します。
- コードを日本語へ言い換えるだけでなく、条件、結果、理由、設計判断、外部仕様上の制約を説明します。
- 早期リターンの直前には、後続処理を行わない理由が分かるコメントを記載します。
- 排他制御、再試行、タイマー世代、重複抑止など、コードだけでは意図を読み取りにくい処理には方針や理由を記載します。
- 単純な代入を言い換えただけの不要なコメントは避けます。

```csharp
// 要求識別子または受信日時が不正か、送信元が想定外の場合は不正要求にします。
if (!request.HasValidIdentifiers( ) || request.Source != "boyomi-proxy")
{
	return this.BadRequest( );
}
```

```csharp
// 正規化後のコメントが発動条件に一致しない場合は、OBS Studioを操作せず正常応答にします。
if (!this.matcher.IsMatch(normalizedText))
{
	return this.Ok(CreateResponse(request.RequestId, false, false, "notRequired", "発動条件に一致しませんでした。"));
}
```

## (14) 属性

- 属性は、属性ごとに別々の角括弧で記載します。
- 複数の属性を同一の角括弧内へまとめません。
- 対象の宣言直前へ、1属性につき1行で記載します。

```csharp
[ApiController]
[EnableRateLimiting("ApiPolicy")]
public sealed class CommentsController : ControllerBase
{
}
```

```csharp
[HttpPost("/api/v1/comments")]
public async Task<ActionResult<CameraEventResponse>> PostAsync([FromBody] CameraEventRequest request, CancellationToken cancellationToken)
{
}
```

## (15) フィールドとコンストラクター

- 依存関係は`private readonly`フィールドへ保持します。
- コンストラクター引数は、対応するフィールドと同じ名前にします。
- フィールドへ代入するときは`this.`を付けます。
- 1つの代入は1行で記載します。

```csharp
this.normalizationService = normalizationService;
this.matcher = matcher;
this.triggerService = triggerService;
```

## (16) 条件分岐

- 早期リターンを使用し、正常系の字下げを深くしません。
- `else if`および`else`は可能な限り避けます。
- 必要に応じてメソッドを分割し、条件ごとに早期リターンします。
- 条件式だけでは業務上の意味が分かりにくい場合、条件分岐の直前にコメントを記載します。
- 否定条件を使用する場合、成立時に何を行うかをコメントで明示します。

## (17) メソッド呼び出し

- 同一インスタンスのメソッドまたはプロパティーを参照するときは`this.`を付けます。
- staticメソッドには`this.`を付けません。

```csharp
string normalizedText = this.normalizationService.NormalizeComment(request.Text);
return this.Ok(CreateResponse(request.RequestId, true, result.Duplicate, result.Operation, result.Message));
```

## (18) 戻り値

- 不要なローカル変数を作らず、意味が明確な場合は直接`return`します。
- `return`の直前に意味のない空行を入れません。
- オブジェクト初期化子の各メンバーは別々の行へ記載します。
- 戻り値の意味は、XMLドキュメントコメントの`returns`へ具体的に記載します。

## (19) ログと例外

- ログメッセージは日本語で記載します。
- 例外ログは、次の形式とします。

```text
エラー概要メッセージ　詳細：例外情報
```

- エラー概要と`詳細：`の間には全角スペースを1つ入れます。
- 例外変数名は`exception`とし、`ex`などへの省略を避けます。
- ログ出力の前後に、意味のない空行を入れません。
- トークン、パスワードなどの秘密情報をログへ出力しません。
- 構造化ログで値を記録する場合も、秘密情報が含まれないことを確認します。

## (20) 規約適用時の優先順位

規約同士の判断が競合する場合は、次の順序で優先します。

1. コンパイルおよび実行上の正しさ
2. セキュリティーと設計書の要件
3. 本コーディング規約
4. プロジェクト内の一貫性
5. 可読性と保守性

規約を例外的に適用できない場合は、その理由を該当箇所のコメントまたはレビュー時の説明へ記載します。
